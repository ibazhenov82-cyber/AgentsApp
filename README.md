# AgentsApp

AgentsApp — Android-клиент для сервиса [AgentsCore](../AgentsCore): весь
UI построен на Jetpack Compose и обращается к AgentsCore исключительно по
HTTP. Приложение не хранит ни истории чатов, ни настроек, ни ключей
LLM-провайдеров — единственная локальная настройка самого приложения это
адрес сервера AgentsCore.

Приложение работает только с актуальными версиями AgentsCore, MCP-сервера
и планировщика: обратной совместимости со старыми серверами нет, версии
API не проверяются — сервисы и приложение обновляются вместе.

## Экраны

### Главный экран (`ui/main`)

Сводный список **агентов** вместе с их **чатами** — главный (и
единственный «домашний») экран приложения.

- Верхняя панель: заголовок и кебаб-меню (⋮) со всеми разделами —
  «Настройки», «Модели», «Профили», «Инварианты», «Модели состояний
  задач», «MCP-сервер» (раньше — отдельные кнопки на панели).
- Плавающая кнопка добавляет нового агента (настройки — из текущих
  настроек по умолчанию AgentsCore).
- Карточка агента: имя, используемая модель (с бейджем «Локальная», если
  модель работает через Ollama), кнопки «Добавить чат», «Настройка
  агента», «Удалить агента» (диалог подтверждения — удаляет агента вместе
  со всеми его чатами и сообщениями), и список его чатов.
- Строка чата: название, счётчики токенов (вход/выход/всего), компактный
  индикатор заполнения контекстного окна (доля от максимума входных
  токенов модели агента), кнопки «Настройка чата», «Копировать чат»
  (диалог с предложенным именем копии, которое можно поменять) и
  «Удалить чат» (с подтверждением).
- **Бейджи настроек** — компактные метки в одну строку рядом с названием
  агента или чата; не поместившиеся сворачиваются в «+N», нажатие
  раскрывает все (с переносом), «Свернуть» — обратно. У чата — только
  настройки, отличающиеся от настроек агента; у агента — только
  отличающиеся от настроек, которые получил бы новый агент
  (`GET /settings/default/agent`: настройки по умолчанию + встроенные
  значения). Выключенная относительно базы настройка показывается явно
  («Потоковые ответы (Выкл.)»). На экране чата — все настройки чата, тоже
  одной строкой с «+N».
- **Идёт ответ**: в строке чата — индикатор загрузки и текущая фаза
  («Выполняется запрос к модели», «Выполняется вызов инструментов» и т.п.).
- **Непрочитанные**: счётчик у строки чата (название — жирным, под ним
  начало последнего сообщения) и общий счётчик у карточки агента.
  Непрочитанное — ответ агента, пришедший, пока чат не был открыт, и
  запросы планировщика. Список обновляется сразу, без ручного
  обновления: новые чаты (в том числе созданные планировщиком — с
  пометкой «по расписанию») появляются сами.
- Пункт меню «Непрочитанные выше» (галочка) — чаты с новыми сообщениями
  поднимаются наверх списка агента; по умолчанию выключено, порядок как
  раньше. Хранится на устройстве.

### Диалог «Подключение к серверу»

Заменяет прежний экран «Подключение к агенту»: поле адреса AgentsCore,
кнопка проверки соединения прямо в диалоге (перенесена сюда из панели
инструментов главного экрана) и сохранение адреса.

### Модели (`ui/models`)

Список моделей, отданных `GET /models` (провайдер, локальная/облачная,
контекстное окно, максимум входных/выходных токенов, лимит токенов на
рассуждения, поддерживаемые возможности), и кнопка «Проверить соединение»
на каждой карточке — дергает `GET /model/{id}/health`, статус
(«Доступна» / «Недоступна» / «Проверка…») отображается тут же.

### Настройки (`ui/settings`)

Один экран на три сценария — настройки по умолчанию, настройки агента,
настройки чата, — управляемых через общий список метаданных полей
(`data/remote/SettingsFieldMeta.kt`), сгруппированных так же, как в
техническом задании: «Модель», «Параметры ответа», «Инструменты»,
«Суммаризация запросов», «Дополнительно». В настройках чата поле «Модель»
только отображается (модель фиксируется на уровне агента). Поле
«Автоматическая суммаризация чата» раскрывает «Предел числа сообщений»
или «Предел числа токенов» только когда выбрано соответствующее значение.
Числовые поля можно оставить пустыми — тогда параметр не передаётся в
запрос к модели. Изменения переключателей/выпадающих списков сохраняются
сразу, текстовые и числовые поля — с debounce после паузы в наборе,
слайдеры — по отпусканию. Настройки по умолчанию дополнительно можно
сбросить к встроенным значениям сервера.

### Чат (`ui/chat`)

- Под верхней панелью — «Агент: …», «Модель: …» (+ бейдж «Локальная»),
  счётчики токенов и заполнение контекстного окна — то же самое, что и
  в строке чата на главном экране, но подробнее.
- Все действия экрана — в кебаб-меню (⋮) верхней панели: «Настройки
  чата», «Память и профиль» (раньше — отдельные кнопки на панели), затем
  «Подготовить суммарный запрос», ветки диалога и панель фактов.
- **Ответ формируется на сервере** (асинхронный запуск): можно уйти в
  другой чат, отправить запрос там и вернуться — черновик продолжит
  дописываться, либо уже будет готовый ответ. Пока ответ формируется,
  вместо «Отправить» — «Остановить» (частичный ответ сохранится с
  пометкой «Остановлено»); набирать следующий вопрос можно.
- Пометки у сообщений: «Остановлено», «Прервано» (сервер перезапускался
  посреди ответа), «Ошибка», «По расписанию» (запрос планировщика).
- При открытии чата — прокрутка к первому непрочитанному и разделитель
  «Новые сообщения»; сообщения отмечаются прочитанными, когда показаны
  на экране.
- «Продолжить»/«Выполнить» Менеджера задач — тоже запуск на сервере:
  «Выполнить» доводит задачу до конца, даже если уйти с экрана чата;
  «Пауза» останавливает серию после текущего шага.
- Пункт «Подготовить суммарный запрос»
  активна только когда в чате есть сообщения, суммаризация не заблокирована
  превышением лимита токенов модели/чата и сейчас не идёт отправка
  сообщения.
- Сообщение с `isSummary = true` отображается как пользовательское, но в
  отдельном (светлом изумрудном) цвете; все сообщения до последнего такого
  summary-сообщения отрисовываются с уменьшенной непрозрачностью — при
  создании нового summary «блёклыми» становятся и предыдущие summary тоже.
- Блок «рассуждения» под ответом ассистента свёрнут по умолчанию и
  разворачивается тапом по сообщению.
- Отдельной кнопки «удалить всю историю» больше нет. Вместо неё —
  выбор сообщений долгим нажатием (или тапом, когда режим выбора уже
  включён): в верхней панели появляется счётчик выбранного и кнопка
  удаления, которая показывает диалог «Удалить выбранное сообщение» / «Удалить
  выбранные сообщения» с кнопками «Удалить»/«Отмена».
- Поле ввода и отправка — запуском на сервере (`POST /chats/{id}/runs`);
  ход ответа приходит событиями запуска, потоково или целиком — по
  настройке чата `stream`.
- Вызовы инструментов (MCP-серверов, памяти, задач, скиллов) отображаются в
  переписке столбиком, по строке-действию на каждый вызов: «Использую
  инструмент GIT API `git_host_get_repo` — Получение информации о
  репозитории». У MCP-инструментов перед именем — источник (поле `group`:
  «GIT API», «Локальный GIT», «HTTP-запросы», «Планировщик» или имя
  внешнего сервера), выделенный цветом темы, как заголовки групп в выборе
  инструментов.
  Значок в начале строки: индикатор загрузки, пока вызов выполняется;
  ключ — вызов завершён; красный значок и текст ошибки под строкой — если
  инструмент вернул ошибку. Источник — событие запуска `tool_call` / поле
  `Message.tool_events`; русские описания — `ui/common/ToolLabels.kt`
  (для инструментов MCP-сервера приоритетно поле `title` из `/api/tools`).
- Бейдж «Инструменты» — в шапке чата и на карточке агента, если в
  настройках выбран хотя бы один инструмент (`tools_json` — непустой
  массив). На главном экране — как и остальные бейджи настроек: только
  если набор инструментов отличается от базы (если убран —
  «Инструменты (Выкл.)»).

### MCP-сервер (`ui/mcp`)

Приложение обращается к MCP-серверу (`../mcp_server`) **напрямую**, по
собственному адресу; AgentsCore подключается к нему отдельно, по протоколу MCP.

- Пункт «MCP-сервер» в меню главного экрана: сколько инструментов, какие
  группы включены на сервере (локальный Git, HTTP-запросы, интернет поиск,
  обработка LLM с названием модели, работа с файлами), список инструментов с
  группой и русским описанием. Инструменты, выключенные настройками сервера,
  в списке не появляются вовсе.
- Раздел «Файлы» (если включена работа с файлами): файлы, сохранённые
  инструментом «Сохранить в текстовый файл» — путь, время, размер, новые
  сверху. Нажатие открывает файл во весь экран: `.md` — с разметкой, остальные
  — моноширинным текстом; вверху — время, размер и начало `sha256`
  (`GET /api/files`, `GET /api/files/content`).
- Кнопка «Git-хостинги» в верхней панели — статус GitHub/GitLab/Gitea:
  настроен ли токен, базовый адрес API, остаток лимита запросов. Хостинг без
  токена остаётся рабочим (анонимный доступ), экран предупреждает о более
  строгих лимитах.

### Планировщик (`ui/scheduler`)

Отдельный сервис (`../scheduler_service`) со своим адресом. Пункт
«Планировщик» в меню главного экрана:

- **Список задач** — вид задачи и расписание словами («ежедневно в 09:00»),
  следующий и последний запуск со статусом, переключатель «включена»,
  «Выполнить сейчас», «Изменить», «Удалить»; задачи, поставленные агентом
  из чата, помечены. Сверху — состояние сервиса: часовой пояс и доступность
  MCP-сервера и AgentsCore.
- **Форма задачи** (кнопка «+» или «Изменить»):
  - «Запрос агенту» — текст запроса;
  - «Задача агенту» — название и описание; выполняется Менеджером задач до
    конца, вопрос агента к человеку появится в чате непрочитанным;
  - «Инструмент MCP» — инструмент из списка MCP-сервера, параметры полями по
    его описанию (строка, число, флаг, выбор из вариантов) или JSON;
    переключатель «Передать результат агенту» с текстом запроса, где
    `{result}` — результат инструмента;
  - для агента — выбор агента и «Куда писать»: в выбранный чат, каждый раз
    в новый чат с названием по шаблону (`{date}`, `{time}`, `{job}`) или в
    чат с заданным названием;
  - расписание — «Каждые N» секунд/минут/часов, «Ежедневно ЧЧ:ММ» или cron;
    время — в часовом поясе планировщика.
- **История запусков** (тап по задаче) — время, по расписанию или вручную,
  число попыток, статус («Выполнена», «Ждёт ответа», «Ошибка», «Прервана»),
  ошибка или результат, кнопки «Открыть чат» и «Открыть задачу».

Ответы и задачи по расписанию приходят в чаты как непрочитанные — их видно на
главном экране, даже если приложение в момент срабатывания было закрыто.

### Выбор инструментов в настройках агента/чата

Поле «Список функций в формате OpenAI» (`tools_json`) — переключатель
«JSON» / «Выбрать из доступных». Во втором режиме инструменты отмечаются
чекбоксами из списка **всех MCP-серверов, подключённых к AgentsCore**
(`GET /mcp/tools`: сервер инструментов, планировщик), с русским описанием,
сгруппированных по источнику (поле `group`): для MCP-сервера продукта — по
категории («GIT API», «Локальный GIT», «HTTP-запросы»), затем
«Планировщик», для внешних MCP-серверов — их короткое имя из
`MCP_SERVERS`. JSON строится из отмеченного набора автоматически. Модели доступны ровно
отмеченные инструменты: ничего не отмечено — ни одного MCP-инструмента.
Инструменты планировщика (`schedule_job`, `list_jobs`, `cancel_job`)
позволяют агенту самому ставить задачи по просьбе в чате: «присылай мне
сюда каждое утро сводку PR».
Переключение между режимами не объединяет изменения — при входе в режим
списка отметки строятся заново по текущему содержимому JSON (по
совпадению имени функции), а при последующей отметке/снятии инструмента
JSON перестраивается целиком.

## Сетевой слой

- `data/remote/AgentsCoreModels.kt` — DTO, дословно повторяющие схемы
  HTTP API AgentsCore (`agents_core/schemas.py`); имена полей — часть
  сетевого контракта, менять их нельзя.
- `data/remote/AgentsCoreApiClient.kt` — клиент на OkHttp: все эндпоинты
  AgentsCore, SSE-подписки на ленту запуска (`runEvents` →
  `Flow<RunEvent>`) и на общую ленту изменений (`globalEvents` →
  `Flow<GlobalEvent>`, ответ `410` приходит как событие `Gone`), отдельные
  типы исключений для ошибки сервера (`AgentApiException`) и
  недоступности сервера (`AgentUnreachableException`).
- `data/remote/RunModels.kt` — запуски, события, непрочитанные.
- `data/repository/RunsRepository.kt` — асинхронные ответы на стороне
  приложения: живёт столько же, сколько процесс (в `AppContainer`), а не
  экран. Отправка создаёт запуск на сервере, подписка на его события
  держится здесь до конца ответа; экраны только читают `observe(chatId)`.
  Пока приложение на экране (`MainActivity.onStart`/`onStop`), держит ещё
  одну подписку — на общую ленту изменений (новые чаты, запуски, начатые
  не этим приложением, непрочитанные) и выдаёт всплывающее «Новый ответ в
  «<чат>»» поверх любого экрана, кроме главного и самого этого чата. В
  фоне подписки закрываются и при возврате продолжаются с последнего
  номера события — без потерь и дублей; при потере ленты (`410`) —
  полная пересинхронизация.
- `data/UiPreferences.kt` — локальные настройки интерфейса («Непрочитанные выше»).
- `data/remote/ServerConnectionSettings.kt` — адрес AgentsCore
  (`SharedPreferences`), по умолчанию `http://10.0.2.2:8000/` (алиас
  хост-машины для Android-эмулятора); настраивается на экране «Настройки»
  (блок «Соединение с сервером»).
- `data/repository/AgentsCoreRepository.kt` — тонкая обёртка над клиентом,
  единственная точка входа для экранов; без собственного кеша — каждый
  вызов уходит на сервер.
- `data/remote/JsonUtils.kt` — `jsonValueOf()` строит `JsonElement`
  (включая явный `null`) для частичных PATCH/PUT-запросов настроек, чтобы
  отличать «поле не передано» от «поле явно сброшено».
- `data/remote/McpModels.kt`, `McpApiClient.kt`, `McpConnectionSettings.kt`,
  `data/repository/McpRepository.kt` — второй, полностью независимый набор
  тех же трёх слоёв (модели/клиент/репозиторий) для отдельного MCP-сервера:
  свой адрес (`http://10.0.2.2:8001/` по умолчанию — тот же алиас
  эмулятора, но порт 8001, см. `mcp_server/config.py:MCPConfig.PORT`),
  настраивается там же, на экране «Настройки» (второе поле блока
  «Соединение с сервером»). Ошибки этого сервиса — отдельные типы
  `McpApiException`/`McpUnreachableException`, чтобы в сообщении
  пользователю было однозначно видно, какой из независимых сервисов
  ответил ошибкой.
- `data/remote/SchedulerModels.kt`, `SchedulerApiClient.kt`,
  `SchedulerConnectionSettings.kt`, `data/repository/SchedulerRepository.kt` —
  третий такой же набор, для планировщика: адрес `http://10.0.2.2:8002/` по
  умолчанию, третье поле блока «Соединение с сервером» в «Настройках»;
  ошибки — `SchedulerApiException`/`SchedulerUnreachableException`.

## Структура модуля

```
app/src/main/java/com/example/agentsapp/
├── AgentsApp.kt, AppContainer.kt, MainActivity.kt   — Application/DI/Activity
├── data/remote/     — DTO, API-клиенты (AgentsCore, MCP-сервер, планировщик), метаданные полей настроек
├── data/repository/ — AgentsCoreRepository, McpRepository, SchedulerRepository, RunsRepository (запуски, непрочитанные, общая лента)
└── ui/
    ├── ViewModelFactories.kt, navigation/AppNavHost.kt
    ├── main/     — главный экран (агенты + чаты)
    ├── models/   — каталог моделей
    ├── settings/ — настройки по умолчанию/агента/чата
    ├── chat/     — экран чата
    ├── mcp/      — статус MCP-сервера, инструменты, Git-хостинги
    ├── scheduler/ — планировщик: задачи, форма, история запусков
    └── theme/    — цвета, тема, типографика
```

## Сборка и запуск

Требуется Android Studio (или Gradle CLI) с Android SDK, `compileSdk`/
`targetSdk` 37, AGP 9.3.0, Kotlin 2.3.20, JDK 17.

```bash
./gradlew assembleDebug
```

Перед первым запуском укажите адрес запущенного AgentsCore в диалоге
«Подключение к серверу» (по умолчанию рассчитан на эмулятор и локально
запущенный AgentsCore на порту 8000 — `http://10.0.2.2:8000/`; для
реального устройства укажите фактический адрес сервера в локальной сети).

**Android 17 и новее: разрешение на локальную сеть.** Приложение с
`targetSdk` 37 на Android 17+ может обращаться к адресам локальной сети
(`10.x`, `192.168.x`, `172.16–31.x`, в том числе `10.0.2.2` эмулятора)
только с разрешением `ACCESS_LOCAL_NETWORK` (группа «Устройства
поблизости»). Без него соединения с AgentsCore, MCP-сервером и
планировщиком обрываются по тайм-ауту, хотя браузер на том же устройстве
адрес открывает. Приложение запрашивает разрешение при первом запуске; если
отказать, его можно выдать в «Настройки → Приложения → AgentsApp →
Разрешения → Устройства поблизости». На Android 16 и ниже разрешение не
требуется.

## Известные ограничения этой сборки

- Провайдер LLM определяется моделью однозначно (каждая модель
  принадлежит ровно одному провайдеру — DeepSeek или Ollama), поэтому
  отдельного выбора «API для модели» в интерфейсе нет — только выбор
  самой модели.
- Значение настройки `seed` для DeepSeek API передаётся «как есть»
  (best-effort): официальный DeepSeek API не документирует этот параметр,
  на стороне Ollama он поддерживается полностью через `options.seed`.
- Планировщик рассчитан на **один запущенный экземпляр** — приложение не
  проверяет, сколько их запущено (см. README `scheduler_service`).
